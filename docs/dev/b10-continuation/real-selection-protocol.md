# Real authorized selection mini-holdout — frozen protocol

2026-10-05. Research-only. The current production candidate remains one strong Agent. This protocol measures whether a bounded candidate-coverage retrieval objective improves two realistic, authorized-context selection tasks. It does not change production MCP, grants, activation, storage, or the Vault.

## Corpus audit and admission

Before model execution, a separate authorized, explicit-Full audit established a minimum supported candidate pool for each task using returned Evidence IDs. Two tasks have adequate support for choosing and comparing at least two documented projects. A third proposed application task needs verified individual roles and outcomes that the audited records do not establish; it is excluded from strict validation and counted as ambiguous support, not a retrieval failure. The private local audit freezes exact task wording, candidate IDs, acceptable alternative pairs, evidence IDs, rubric, sequence 66, policy epoch 1, and the current grant. The audit demonstrates minimum support, not exhaustive corpus recall or personal contribution.

## Fixed comparison

- **A:** GPT-6 Astra xhigh, current ordinary strong-single Aptuni path and its installed adapter. No research policy.
- **B:** Same model, ordinary task wording, and existing grant, with a disposable bounded roster and Evidence fetch. The research wrapper permits up to 12 authorized Knowledge/GitHub source groups in 1400 response units, then Evidence for up to three disclosed anchors in 2600 units, with a two-call/4000-unit aggregate cap. It prefers each group's README before stable-ID ordering and rechecks activation, grant scope, exposure, credentials, and canonical sequence on every call. A label alone never counts as Evidence.

Both arms use fresh ephemeral Codex sessions, explicit empty Full setup, existing Codex grant, the same frozen Vault snapshot and knowledge scope, and no unrelated host tools, memory writes, filesystem, or web access during tasks. B is a research-only tool contract, not a proposed public interface. A retains its current relevance-oriented retrieval allowance. All four task sessions are run once, in order s01 A, s01 B, s02 B, s02 A. No quality inspection, retuning, task replacement, or rerun between sessions. Operational failures remain in the denominator. Snapshot or authorization drift stops the comparison.

## Grading and decision

Grade against the frozen goal-derived rubric and the actual returned Evidence, then unmask arm and resource use. Record corpus adequacy; candidate groups returned as Evidence; relevant candidate precision and recall against the audited minimum pool with its non-exhaustive caveat; pair selected; support for consequential claims; requested comparison completion; activation correctness; strict E2E; R0–R4 stage failures; calls, retries, tokens, and journey latency. Report raw counts before percentages. A pair may pass through any predeclared acceptable alternative. No source title alone proves owner work or results. An omitted comparison is R4 unless evidence shows an earlier causal failure. An R4 pattern may motivate a separate fresh test of a small completion policy; it may not be repaired and regraded on this mini-holdout.

Promote a lightweight selection retrieval objective only if it materially improves real strict E2E at reasonable cost and leaves no product-critical failure. If quality ties, keep A. If retrieval succeeds but comparison completion fails, freeze that finding and investigate completion separately. No Agent-directed retrieval or multi-Agent variant is in this phase. Two tasks cannot establish a population reliability rate. b10 remains unreleased unless a subsequent appropriate release gate establishes reliable E2E behavior.
