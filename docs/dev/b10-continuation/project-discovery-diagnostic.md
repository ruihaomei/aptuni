## Concrete code limitation

`SqliteProjection.documents_for()` indexes statement, else excerpt, else subject.
Repository identifiers and display labels in Evidence locator metadata are not
part of ordinary concept search. Context packing omits locator fields; no host
project/source discovery endpoint exists. The owner-only source inventory is not
a permitted replacement: SourceConfig is not an exposable record.

GitHub Evidence has stable repository identifiers and bounded metadata capable of
supporting an anchor projection. Any prototype must derive it only from current
exposable Evidence, recheck the exact host/module/evidence grant and activation,
charge labels as personal context, preserve credentials/taint/citations/budgets,
and ground project claims in a subsequent bounded evidence response. A label is
never proof of owner work or competence.

The frozen [synthetic contrast](synthetic-discovery-probe.json) tests unknown
supported work versus study-only material with identical impressive labels.
It includes discovery **and exact-anchor evidence access**, not labels alone.
Its five-entry exhaustive toy catalog cannot establish candidate selection at
110k-record scale. Success would justify one minimal proposal, not production
shipping or a release. Failure stops implementation.

**Verdict:** **DISCOVERY GAP SUPPORTED — test the tiny permissioned mock before adding runtime agents or a production catalog.**
